# 2026-06-06 工作记忆

## 第二步文稿/板书 rows JSON 入口修复

- 用户现象：第二步“生成文稿板书内容”的对话里出现 `Bad escaped character in JSON at position 263 (line 1 column 264)`。
- 对应关系已核对：
  - 界面第二步只生成候选 `rows`。
  - `rows[].voiceText` 是讲解文稿候选。
  - `rows[].boardSlice` 是 C 素材候选，也就是课堂板书内容候选。
  - 用户确认应用后，compiler 才把 rows 编译成正式 `spokenScript` / `boardPlan`，再由 store 写入正式 `scriptText` / `boardLayout`。
- 根因定位：
  - 报错发生在模型输出进入 rows 前的网关 `JSON.parse(jsonText)`。
  - 模型可能把 LaTeX 写成 JSON 字符串里的单反斜杠，如 `\left`、`\frac`、`\div`，其中部分会触发 `Bad escaped character`，部分会被 JSON 控制字符吃坏。
- 已改：
  - `scripts/script-agent-rows-contract.mjs` 新增 `parseJsonWithMathStringEscapes()`，只修复 JSON 字符串内部明确数学/LaTeX 命令反斜杠。
  - `vite.config.mjs` 的本地 `/api/agent/script-board` 使用共享 parser。
  - `scripts/zeabur-server.mjs` 的 Node/部署 `/api/agent/script-board` 使用共享 parser。
  - `scripts/check-script-agent-rows-contract.mjs` 加入未转义 LaTeX 反斜杠回归，并把 Node 路径改成优先 portable runtime、否则 `process.execPath`。
- 验证：
  - 直接 Node 复现未转义 `\left/\frac/\div`：通过，rows 保留 LaTeX 并编译到 `B1/C1`。
  - 直接 Node 验证合法 JSON `\n`：通过，未被误修成字面反斜杠。
  - 直接 Node 验证未知非法转义：通过，继续拒绝进入老师讲稿/板书候选。
  - `npm run check:script-agent-rows`：通过。
  - `npm run typecheck`：通过。
- 下一棒：
  - 回到 `src/modules/boardSticker/mathBoardText.ts`，修普通 C 文本换行被压扁的问题。
  - 不要改 rows 合同；`boardSlice` 和用户 `\n` 仍是内容真相。

## 产品语义纠偏

- 夏夏指出：这类细节错不可原谅，产品开发不能只看到技术。
- 已纠正：
  - 不再使用 loose/宽松口径。
  - 第二步 JSON parser 的产品边界是保护老师讲稿/课堂板书中的数学表达。
  - 只修复明确数学/LaTeX 反斜杠和数学定界符。
  - 未知非法转义必须暴露错误，不能偷偷进入候选内容。
- 后续纪律：
  - 每次修第二步或 C 板书链路，都要先讲清产品含义：老师讲什么、黑板写什么、学生看见什么。
  - 第二步 JSON 修复不叫“容忍模型错误”，而是保护课堂数学表达；未知非法转义必须失败。
