## 分片 chrome + 自由画布纠偏

- 用户纠正：不能再按固定四区版式理解；“标签 + 容器 + 分片内容”是一组可复用内容展示模块，旧固定限制区域应解除。
- 代码实证：
  - 之前只有 `coursewareZoneLayout.ts` 做 bbox 计算，`DrawboardStage.tsx` 分散渲染标签、容器框、题目正文和 C children，不是真模块。
  - `AutoHandwritingLayer.tsx` 旧 `constrainYPercentToZone` 会把 C 的 `yPercent` 拉回 `COURSEWARE_ZONE_BOUNDS`，与自由画布冲突。
- 本轮改动：
  - 新增 `CoursewareSegmentChrome`，只管标签 pill + 可选容器框，保持扁平 DOM，不包 C 内容。
  - 移除 C 固定四区 y clamp；`chainKey` 只决定分片身份和 `board-text-sticker--zone-*` / `data-agent-zone` 归组。
  - 分片容器仍由真实内容 bbox + `5px` padding 生成；容器 `pointer-events: none`，只有标签 pill 可拖。
  - 题目正文非加粗，字号 = 标签字号 `1.5` 倍；题目区不显示蓝色虚线框。

## 普通 C 实时文本

- 用户指出截图里普通 C 字体变异，且甲方允许正常实时打字，不需要普通 C 走图片方式。
- 本轮改动：
  - `BoardHandwritingStickerContent` 从 PNG `<img>` 改成 DOM 实时文本 `<span data-render-mode="realtime-text">`。
  - `AutoHandwritingLayer` 录制普通 C 改成 canvas 实时文字绘制；复杂公式继续走 `renderBoardMathStickerImage`。
  - `renderBoardTextStickerImage` 保留为备用/旧路模块，但不再是普通 C 主路。
- 守门：
  - `check-board-boundaries` 禁止普通 C 回到 PNG 主路，禁止固定四区 clamp 回潮。
  - `check-board-handwriting-support` 改为本地 runtime 存在才用，否则回退 `process.execPath`，避免本机路径硬编码导致验证失效。
