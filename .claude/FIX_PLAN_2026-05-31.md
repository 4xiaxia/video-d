## 问题1：C 文字没有按标签领地站位

### 根本原因

`TimelineClip` 有 `chainKey`，但 `AutoHandwritingLayer` 没有用它来约束渲染位置。
- 四区标签（chrome）已有几何定义：`coursewareChrome.ts`
- 四区标签和 C 文字的映射关系**断了**

### 修复方案

#### 方案A（推荐）：自动吸附到四区

**改动点：**
1. 在 `coursewareChrome.ts` 中补充四区的高度范围定义
2. 在 `AutoHandwritingLayer` 中添加"约束逻辑"
3. 当 C 被拖放时，自动吸附到对应四区

**代码改动位置：**

```typescript
// src/modules/canvasStage/coursewareChrome.ts 补充

export const COURSEWARE_ZONE_BOUNDS = {
  problem: {
    topRatio: COURSEWARE_LABEL_TOP_RATIOS.problem,
    bottomRatio: COURSEWARE_LABEL_TOP_RATIOS.analysis, // 下一个区的顶部
    heightRatio: COURSEWARE_LABEL_TOP_RATIOS.analysis - COURSEWARE_LABEL_TOP_RATIOS.problem,
  },
  analysis: {
    topRatio: COURSEWARE_LABEL_TOP_RATIOS.analysis,
    bottomRatio: COURSEWARE_LABEL_TOP_RATIOS.solution,
    heightRatio: COURSEWARE_LABEL_TOP_RATIOS.solution - COURSEWARE_LABEL_TOP_RATIOS.analysis,
  },
  solution: {
    topRatio: COURSEWARE_LABEL_TOP_RATIOS.solution,
    bottomRatio: COURSEWARE_LABEL_TOP_RATIOS.summary,
    heightRatio: COURSEWARE_LABEL_TOP_RATIOS.summary - COURSEWARE_LABEL_TOP_RATIOS.solution,
  },
  summary: {
    topRatio: COURSEWARE_LABEL_TOP_RATIOS.summary,
    bottomRatio: 1.0,
    heightRatio: 1.0 - COURSEWARE_LABEL_TOP_RATIOS.summary,
  },
} as const;

export function getZoneBoundsFromChainKey(chainKey: string | undefined) {
  if (chainKey === 'template-open') return COURSEWARE_ZONE_BOUNDS.problem;
  if (chainKey === 'template-pre' || chainKey?.startsWith('template-pre-')) return COURSEWARE_ZONE_BOUNDS.analysis;
  if (chainKey?.startsWith('step-')) return COURSEWARE_ZONE_BOUNDS.solution;
  if (chainKey === 'template-end' || chainKey?.startsWith('template-end-')) return COURSEWARE_ZONE_BOUNDS.summary;
  return null;
}

export function constrainYPercentToZone(yPercent: number, zoneBounds: typeof COURSEWARE_ZONE_BOUNDS[keyof typeof COURSEWARE_ZONE_BOUNDS]) {
  const topPx = zoneBounds.topRatio * 100;
  const bottomPx = zoneBounds.bottomRatio * 100;
  return Math.max(topPx, Math.min(yPercent, bottomPx - 5)); // 留一点余量
}
```

**在 AutoHandwritingLayer 中使用：**

```typescript
// src/components/AutoHandwritingLayer.tsx

}

```

## 问题2：B 播放完毕，C 默认躺平不下台

### 根本原因

当前 `isPlayheadInsideTimelineWindowWithPinnedEnd` 的行为：
- `playheadMs <= endMs` → C 可见
- `playheadMs > endMs` → C 被过滤掉（消失）

但用户需求是：
- `playheadMs > endMs` → C 继续显示（演绎完毕的静态态）
- 用户可以在时间线上拉长 C 的时长来改变"留场时长"

### 修复方案

#### 方案A（推荐）：改进 C 的可见性逻辑

不改变 `isPlayheadInsideTimelineWindowWithPinnedEnd` 的定义（这个函数可能被其他地方使用），而是在 AutoHandwritingLayer 中添加新的过滤逻辑：

```typescript
// src/components/AutoHandwritingLayer.tsx

// 替换原来的 filter 逻辑
const visibleBoardClips = useMemo(() => {
  return boardClips
    .filter((clip) => {
      // 新规则：C 在 B 演绎完毕后可以继续留场
      // 只在"已经过时很久"时才过滤掉（例如超过 5 秒）
      const timeoutMs = 5000; // 可配置
      const isExpired = playheadMs > clip.endMs + timeoutMs;
      
      if (isExpired) {
        return false; // 真的过期了，过滤掉
      }
      
      // 否则，只要 playheadMs >= startMs，就保持可见
      return playheadMs >= clip.startMs;
    })
    .sort(compareBoardClipLayerOrder);
}, [boardClips, playheadMs]);
```

**但这样改可能太激进**。更保险的做法是：

#### 方案B（更稳妥）：添加 C 的"留场标志"

在 TimelineClip 中补充一个标志，表示"这个 C 是否应该在 B 到期后继续留场"：

```typescript
// src/domain/teachingProject.ts

export type TimelineClip = {
  // ... 现有字段
  pinnedAfterEnd?: boolean; // 新增：是否在 B 到期后继续显示
};
```

然后在 AutoHandwritingLayer 中使用：

```typescript
const visibleBoardClips = useMemo(() => {
  return boardClips
    .filter((clip) => {
      const inNormalWindow = isPlayheadInsideTimelineWindowWithPinnedEnd(playheadMs, clip.startMs, clip.endMs);
      
      if (inNormalWindow) {
        return true;
      }
      
      // B 到期后，检查是否应该留场
      if (clip.pinnedAfterEnd && playheadMs > clip.endMs && playheadMs < clip.endMs + 30000) {
        // 留场时间最多 30 秒（或根据新的 uiEndMs 字段）
        return true;
      }
      
      return false;
    })
    .sort(compareBoardClipLayerOrder);
}, [boardClips, playheadMs]);
```

**补充：用户拉长时长的交互**

在时间线上，当用户拖拽 C 块的右边界时，实际上是在修改 `endMs`。这已经由时间线组件处理了，只需确保修改被正确保存到 store 中。

#### 方案C（最完整）：引入两个时间端点

为 C 补充两个时间端点，分离"演绎"和"留场"的概念：

```typescript
export type TimelineClip = {
  // ... 现有字段
  startMs: number;        // B 开始（C 出现）
  endMs: number;          // B 结束（C 演绎完毕）
  pinnedEndMs?: number;   // 新增：C 留场的最晚时间
};
```

这样的好处是：
- `startMs` ~ `endMs`：C 逐笔演绎
- `endMs` ~ `pinnedEndMs`：C 演绎完毕，静态显示
- `pinnedEndMs` 之后：C 消失

在 AutoHandwritingLayer 中：

```typescript
const visibleBoardClips = useMemo(() => {
  return boardClips
    .filter((clip) => {
      const effectiveEndMs = clip.pinnedEndMs ?? clip.endMs;
      return playheadMs >= clip.startMs && playheadMs <= effectiveEndMs;
    })
    .sort(compareBoardClipLayerOrder);
}, [boardClips, playheadMs]);
```

在逐笔动画中：

```typescript
// 当 playheadMs > clip.endMs 时，冻结 revealProgress
const shouldFreezeReveal = playheadMs > clip.endMs;
const revealProgress = shouldFreezeReveal
  ? 1.0 // 逐笔完成，100% 显示
  : calculateRevealProgress(clip, playheadMs);
```

### 验收标准

- [ ] B 播放完毕后，C 不会立即消失
- [ ] 用户可以在时间线上拖拽 C 的右边界来拉长留场时长
- [ ] 当 pinnedEndMs 到达时，C 才真正消失
- [ ] 播放器能正确同步新的时间端点
