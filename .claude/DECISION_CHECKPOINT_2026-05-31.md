## ✅ 问题2：B 播放完毕，C 默认躺平不下台

**现象：** B 的寿命窗口(endMs)到了，C 应该消失或被用户拖走，但目前 C 会立即消失

**需求解读：**
- B 到期后 → C 不立即消失，而是"躺平"显示（演绎完毕的静态态）
- 用户可以手动点击/拉长 → 改变 C 在舞台的停留时长

### 选择方案

**方案 A - 粗暴延时**
```
添加 5 秒超时，超过 5 秒才过滤掉 C
改动：AutoHandwritingLayer.tsx（只改逻辑）
风险：低，但不够灵活（用户无法精调）
```

**方案 B - 添加 pinnedAfterEnd 标志**
```
在 TimelineClip 中补充 pinnedAfterEnd 布尔字段
改动：teachingProject.ts + AutoHandwritingLayer.tsx
风险：低（布尔字段，默认 false 向后兼容）
```

**方案 C（推荐）- 引入 pinnedEndMs 字段** ✨
```
为 C 补充两个时间端点：
  - endMs：演绎完毕时间（当前有的）
  - pinnedEndMs：留场结束时间（新增）

startMs ──────────── endMs ────────── pinnedEndMs
  ↓                     ↓                ↓
C 出现            逐笔完成          C 消失
            [逐笔演绎阶段]  [静态留场阶段]

改动：teachingProject.ts + AutoHandwritingLayer.tsx + 编译逻辑
好处：完全分离"演绎"和"留场"的语义，便于时间线交互
风险：中（需要更新编译链路，但可向后兼容）
```

- [ ] 方案 B（中等灵活性）
- [ ] 方案 C（最完整的语义）
