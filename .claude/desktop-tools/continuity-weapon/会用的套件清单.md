# 会用的套件清单

> 这不是硬绑定清单。它说明“秩序专武”会调用或建议接入哪些能力层。具体路径写进 `scripts/continuity-stack.config.json`，不写死进规则包。

已安装套件的调用方式、使用场景和缺口见：

```text
.claude/desktop-tools/continuity-weapon/已安装套件调用说明.md
```

原则：渐进式安装。缺哪个命令装哪个命令；smoke 通过后才升级为 required；候选只登记，不默认启用。

## 核心必需

```text
PowerShell
  -> 运行 continuity-weapon 的入口脚本

Node.js
  -> 运行 audit-local-order.mjs / install-continuity-standard.mjs / install-system-skill.mjs

local-continuity-standard
  -> 规则包本体：五件套模板、审计、安装引导
```

## 工作流编排层

用途：把“开工秩序、检查、导出、运行、MCP 编辑”做成可视化和可执行 workflow，而不是散在口头流程里。

候选套件：

- `cc-wf-studio`

仓库：

- `https://github.com/ourzeta/cc-wf-studio`

组件：

```text
cc-wf-studio/packages/
├── core    -> workflow.json 核心格式与共享逻辑
├── cli     -> ccwf render / validate / export / run / preview / canvas / mcp
├── mcp     -> ccwf-mcp，给 AI client 读写 workflow
└── vscode  -> 可视化 React Flow 工作流编辑器
```

适合接入的位置：

```text
秩序专武
  -> 生成/检查 workflow.json
  -> ccwf validate
  -> ccwf export 到 .codex/skills 或 .claude/commands
  -> ccwf-mcp 允许 agent 读写 workflow
```

配置方式：

```json
{
  "command": "ccwf"
}
```

```json
{
  "command": "ccwf-mcp"
}
```

边界：

- 不默认安装。
- 不把 workflow studio 当缓存层或压缩层。
- 先用 CLI/MCP 小范围试点，再决定是否装 VS Code extension。
- workflow 文件应作为“流程资产”，不能替代 `PROJECT_STATE.md` / `ENGINEERING_LOG.md` / `DECISIONS.md`。

## 本地模型/分流层

用途：把摘要、提取、分类等 bounded tasks 分给便宜模型或本地模型。

候选套件：

- `houtini-lm`（候选，未默认安装）
- `cc_token_saver_mcp`（暂不优先）

可选命令：

```json
{
  "command": "houtini-lm"
}
```

边界：

- `houtini-lm` 优先级高于 `cc_token_saver_mcp`，因为它更像完整分流层。
- `cc_token_saver_mcp` 保留为 MCP token saver 候选，不能和其他会改同一 MCP/token-saving 层的工具同时启用。

## 配置原则

- 规则包本体不写死任何路径。
- 项目要强审计，就把需要的路径写入 `scripts/continuity-stack.config.json`。
- 某台机器换目录，只改配置，不改规则包。
- 候选工具只列为 optionalCommands，不自动安装。
