# 阿里云 TTS 数学语音当前真相

这条记录只管 A 轨语音入轨文本，不管 B/C 板书显示，也不管 C 手写字体。

## 文档依据

`doc/语音资料/阿里云语音的摘抄.md` 记录了 CosyVoice 数学公式朗读规则：

- 公式需要用分隔符包裹，支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`。
- JSON 或代码字符串里的反斜杠要转义。
- 支持基础数学、部分特殊数学符号、几何、条件、单位等标签和符号。
- 语种限制：仅支持中文。
- 分隔符内只应包含公式，否则语音合成结果可能不准确。
- 不支持 Markdown 代码块形式的数学公式。

## 项目边界

A 轨是讲给人听的语音文本。B/C 是给人看的板书和演绎文本。两者可以同源，但不是同一份字符串。

所以必须区分：

- A speech text：送阿里云 / CosyVoice 的可朗读文本。
- B board text：板书贴片内容。
- C handwriting text：手写演员实际渲染内容。

不能把 B/C 显示层的公式、符号、LaTeX、手写字体 fallback 直接混进 A 轨语音入参；也不能为了让语音好读而反向改坏 B/C 的显示文本。

## 当前处理原则

- 简单口播可以直接进入 A 轨。
- 数学公式进入 A 轨前，要按阿里云规则做公式包裹或读法转换。
- 小学数学场景优先稳定自然读法，不追求把所有复杂 LaTeX 都塞进 TTS。
- B/C 的可视内容保留板书表达；A 的语音内容可以是经过滤网的朗读表达。
- `boardSlice`、C 手写字体支持、阿里云 TTS 公式支持是三件事，不能混成一个“数学支持”判断。

## 后续检查口径

当语音读法异常时，先查：

1. 送入 TTS provider 的文本是否已经过语音滤网。
2. 公式是否被 `$...$` 等分隔符正确包裹。
3. 反斜杠是否在 JSON / 字符串里正确转义。
4. 分隔符内是否混入了非公式说明文字。
5. A 轨语音入参是否误用了 B/C 显示文本。

当 C 显示异常时，不要用阿里云语音规则解释；先查 C 渲染、字体、公式分流和 fallback。
